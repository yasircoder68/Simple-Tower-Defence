# Zero-Asset UI Plan

Companion to [implementation_plan.md](implementation_plan.md). Covers the HUD and interface
system for **Medieval Horde Defense**, built with no art assets.

Rendered version: https://claude.ai/code/artifact/ccaeebb6-0161-4a7d-a72e-ba13bb66fb0d

**~16h across 6 stages. UI-0 has no dependencies and is buildable today.**

> **Alpha's A4 takes UI-0, a trimmed UI-1, and UI-4** — the minimum that lets a stranger play.
> **UI-2, UI-3 and UI-5 are deferred to beta**, which owns an *All UI screens finished* pass.
> None of the three blocks a release. See [a4_plan.md](a4_plan.md).

## The open decision

Restrained dark fantasy, or push procedural parchment? **You don't have to answer yet.**
The whole look resolves from ~15 colour constants in one file, so the aesthetic is a
parameter, not an architecture. Pick after UI-0 exists and you can see it.

---

## Architecture

One `Theme` resource, generated by a script from a palette file.

Godot's `Theme` cascades to every `Control` in the project. Set it once in `ProjectSettings`
and every Button, Panel and ProgressBar inherits it — hover, pressed and disabled states
included, with no per-node wiring.

The theme is **generated, not hand-authored**, because: a palette change becomes one command
instead of forty inspector clicks; a hand-edited `.tres` is a merge-conflict magnet; and the
generator doubles as documentation of what each style actually is.

```gdscript
# game/ui/palette.gd — the entire reskin surface
const BG        := Color("#14110f")  # warm near-black, never pure
const SURFACE   := Color("#1e1a17")
const RAISED    := Color("#2a2420")
const BORDER    := Color("#3a322b")
const GOLD      := Color("#c9a227")  # accent: currency, trim, focus
const BLOOD     := Color("#b8453f")  # semantic: damage, lives lost
const TEXT      := Color("#e6ddd0")
const MUTED     := Color("#9a8f80")
```

Neutrals are biased warm toward the gold rather than sitting on pure grey.

## Stages

Numbered because it is a real dependency chain — UI-0 gates everything, and the HUD cannot
exist before the systems it displays.

### UI-0 — Theme foundation · ~2h · **no dependencies**
- `ui/palette.gd` — the colour constants above
- `scripts/tools/build_theme.gd` — `@tool` generator emitting `ui/game_theme.tres`
- StyleBoxes: panel, raised, inset, button ×4 states, progress track + fill
- Type scale — display 32 / h1 24 / h2 18 / body 14 / small 11
- Register via `gui/theme/custom` so it applies project-wide

### UI-1 — The HUD · ~3h · needs UI-0 + economy, lives, waves
- `hud.tscn` / `hud.gd` on a `CanvasLayer`
- Gold, wave `3 / 20`, lives, kills — tabular figures so they don't jitter
- Signal-driven off the managers; nothing polls in `_process`
- Gold gain tweens a count-up; a lost life flashes a vignette
- Absorbs the loose FPS label currently sitting in `map1.tscn`

### UI-2 — Build sidebar rebuild · ~2h · needs UI-0 + economy
- `build_sidebar.gd` currently constructs its whole UI imperatively at runtime — convert to
  a real scene
- Tower cards: name, cost, icon, hotkey
- Affordability state — dim and desaturate when gold < cost, so the constraint is visible
  before the click
- Selected state, and a hover tooltip carrying damage / rate / range

### UI-3 — Procedural icons and texture · ~3h · needs UI-0
- `icon_factory.gd` — tower and enemy glyphs via `_draw()` into a cached `ImageTexture`
- `NoiseTexture2D` + `FastNoiseLite` for parchment or weathered-stone grain, if taken
- The MCP toolkit's `placeholders` group generates prototype textures too — faster, lower ceiling
- Replaces the 181-byte placeholder pixels currently used as button icons

### UI-4 — Screens · ~4h · needs UI-0 + waves, lives, the economy
- Wave banner — announces each wave, tweens in and out
- Game over — waves survived, kills, gold awarded, and **silver kept** (there is no "souls"
  currency; that was removed by decision 2026-09-03 — silver and gold only). **Saying the silver
  was kept is not a nicety:** a fresh save loses level_01 at wave 4 by design, so a new player's
  first result screen is a loss, and today it never explains that their progress survived it.
- **Pause — Resume / Restart / Quit to menu.** There is no pause in the game at all today.
- Main menu — Begin Defense / Upgrades / Quit
- Upgrade shop as its own screen, not a panel wedged beside the tower sidebar

**A4 builds this stage.** See [a4_plan.md](a4_plan.md) for the work order, the pause policy, and
the scene-replacement constraint that keeps `/root/map1` valid.

### UI-5 — Juice · ~2h · ongoing
- Shaders — glow on gold gain, vignette when lives run low, button hover bloom
- Screen shake on heavy AoE, on the same bus as the life-lost flash
- A `reduce_motion` setting that mutes all of the above

## This changes the build order

`implementation_plan.md` puts the HUD at position **8**, after economy, lives, waves, the enemy
refactor and three new towers. That means five systems get built and hand-tested with no
interface, then a HUD gets bolted on.

**UI-0 has no dependencies.** Build the theme first — two hours, unblocked now, and every
screen afterwards is styled from birth. Then build each Phase 1 manager together with the
piece of HUD that displays it.

| Order | Work | Effort |
|---|---|---|
| 1 | UI-0 — theme foundation | 2h |
| 2 | Economy manager *+ its gold readout* | 3h |
| 3 | Base health *+ lives readout, game over screen* | 4h |
| 4 | Wave manager *+ wave counter, wave banner* | 5h |
| 5 | UI-2 — build sidebar rebuild | 2h |
| 6 | UI-3 — procedural icons | 3h |

## Honest ceiling

| Target | Reachable | How |
|---|---|---|
| Clean dark-fantasy HUD, styled controls | **Fully** | StyleBoxFlat + Theme |
| Weathered parchment / stone panels | **~70%** | NoiseTexture2D + shader |
| Readable tower & enemy icons | **Fully** | `_draw()` glyphs |
| Ornate filigree, gilded frames | **No** | needs real textures |
| Illustrated tower portraits | **No** | needs an artist |

The trap is aiming at ornate, missing, and landing on cheap. Committing to restrained and
high-contrast reads as a deliberate style — that is the recommended direction.

One thing worth actually sourcing: a display face. Godot's default is legible but generic, and
a free Google font (Cinzel, MedievalSharp) is a ~200KB `.ttf` that changes the feel more than
any other single change.

Every stage is independently shippable — none leaves the game broken, so this can be
interleaved with gameplay work rather than run as a block.
